## Prisma Module Resolution Analysis

### Node.js 22 ESM Requirements

**Why `.js` is needed:**

Node.js ESM module resolution requires explicit extensions for **local relative imports**. This is per Node.js ESM specification.

**Why it works in Next.js:**

Next.js uses a bundler (Webpack/Turbopack) that:

- Strips TypeScript during compilation
- Resolves all extensions automatically
- Handles module resolution for you

**Why it fails in direct Node.js:**

Direct Node.js execution with `--experimental-strip-types`:

- Strips TypeScript on-the-fly
- Does NOT handle extension resolution
- Requires explicit `.js` or `.ts` extension

**Solution Applied:**

Changed `./generated/client` → `./generated/client.js`

This works because:

1. `client.ts` is the source file
2. Node.js looks for `client.js` (bundled/built version)
3. Alternative: `client.ts` also works with `--experimental-strip-types`

**Recommendation:** Use `.js` for consistency.
